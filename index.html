战斗深度 Roadmap · 下一步做什么 v5

战斗核心已跑通，"像 Brotato 硬打 + 升级系统"其实已经有了。接下来往三个方向加深度，避免停在纯数值堆叠：

A · 局内 Build 深度 最高优先级 P1雏形已实装

造化卡池扩展：除数值卡外加入法宝卡（掉落新武器，多槽位并行开火，对标吸血鬼幸存者）；进化组合——某法宝满级 + 特定造化 → 究极形态（直接落地本页《武器基座 + 进化组合》那张表，如 惊鸿剑气 + 符箓 → 剑气化虹 360°）。复用现有 Modifier 承接词条。

产出："每局不同 build"的重复可玩性——最能拉开与 Brotato 差距的护城河。工作量最大。

✅ 已落地：剑气化虹进化链（惊鸿剑气·凝 ×3 + 符箓术 → 360°环绕剑气 + 范围/伤害爆发）。

B · 局外门派养成 留存

灵石现在算出来了却没处花。加局外灵石消费：买永久强化（弟子功法、初始法宝、初始造化），对接企划案"局外门派养成"层，一局强于一局。

产出：给"再来一局"一个理由。中等工作量。

C · 境界突破 + 内容节奏 性价比最高

"道行 Lv" 重构为修真境界（练气→筑基→金丹→元婴…）；到境界节点触发破境——一次"大造化"稀有三选一 + 破境光效 / 短暂力量爆发。再扩第二章（雪山 / 魔窟）+ 新妖王。

产出：节奏爆点 + 仙侠代入感。最便宜，最快出味。

建议推进顺序：C（便宜、立刻出仙侠味）→ A（Build 深度护城河）→ B（长线留存）。若以 Steam Demo 差异化为首要目标，可 A 优先。

四层无限成长栈

① 局内 · 法宝进化 P1 已落地

每局重置的 Build 深度。造化三选一 → 法宝进化组合。剑气化虹已实装（惊鸿剑气·凝 ×3 + 符箓术 → 360°环绕剑气 + 范围/伤害爆发）。后续扩到 20+ 条进化链。

爽点：每局都不一样，追"这局能不能凑出化虹"。

② 洞府养成 跨局 Meta

灵石带出战斗，花在永久强化：弟子功法树、初始法宝、洞府设施（丹房 / 聚灵阵 / 藏经阁）。一局强于一局——"再来一局"的直接理由。

爽点：今天变强了，明天能进更深的秘境。

③ 修真境界 · 挂机脊柱 无限

练气→筑基→金丹→元婴→化神→…无上限。闭关时离线挂机产灵气（Cookie Clicker 味），攒够一次性突破：破境光效 + 全属性阶跃。境界解锁新功法 / 新秘境层。

爽点：永远有下一境；离线也在涨；回来就有大突破。

④ 飞升 · 转生 Prestige 软重置

境界到顶后飞升：重置境界，换取永久"仙道"加成（产出倍率、造化质量、上界内容）。对标 Cookie Clicker 转生 / 天堂芯片，把"无限"变成螺旋上升而非线性膨胀。

爽点：重置反而更强，开启更快的新一轮成长。

每日循环（留存钩子）

上线 → ① 收离线闭关灵气、看能否突破境界 → ② 洞府花灵石买 1-2 个永久强化 → ③ 下 1-3 局秘境（局内法宝进化爽一把）→ ④ 带灵石回洞府、推进境界 → 明天更深的秘境层解锁 → 循环。每一步都有"变强了"的即时反馈。

怎么防"数值跑步机"（越强越无聊）

核心风险：无限成长最容易变成"数字虚高、内容原地踏步"。四道闸解决：
  • 无尽秘境：深度层数无限、敌人指数缩放——给无限力量一个无限去处（对标雅典娜无限难度）。
  • 广度 > 纯深度：每个境界解锁新机制 / 新功法 / 新法宝，让成长带来"新玩法"而非"同一件事数字更大"。
  • 灵气 / 灵石 Sink：飞升、突破、法宝合成持续消耗资源，避免数值通胀到无意义。
  • 固定主线锚点：章节剧情 / 妖王是有限、手工设计的里程碑，给无限刷一条有终点的叙事线。

多人联机设计 v3新增

  • 联机形式：局内共享同屏联机（4人对抗同一波怪，对标暗黑地牢/元气骑士），局外门派养成各自独立，避免进度绑定摩擦

数值曲线示例（已删除抽卡保底公式）

v2的抽卡保底公式在88抽即溢出概率100%，属于数值bug。v3已删除该设计，改用天然0-1封顶的局内随机词条权重系统。
# 角色基础伤害成长
base_damage(level) = 10 * (1.08 ^ level) + level * 2

# 章节难度曲线（替代无限刷图节奏）
enemy_hp(chapter, wave) = 50 * (1.12 ^ chapter) * (1.05 ^ wave)

# 局内随机词条池权重（三选一，天然不会溢出）
def weapon_choice_weights(rarity_pool):
    return normalize([w.base_weight * w.rarity_modifier for w in rarity_pool])

# 联机同屏难度补偿
enemy_hp_coop(base_hp, player_count) = base_hp * (1 + 0.6 * (player_count - 1))

备注：所有公式写入正式配置前必须做边界值验算——上一版保底公式溢出就是活生生的反例。
